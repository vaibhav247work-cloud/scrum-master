# Company OS Frontend

This is the responsive React/TypeScript/Vite frontend shell for the Company Operating System.

The current shell reflects the frozen frontend baseline:

- Home
- My Work
- My Team
- Sprints
- Projects
- Responsive mobile navigation
- Light/dark themes
- Indigo/blue/cyan semantic gradient tokens
- Reduced-motion support
- TanStack Query provider for server state
- Employee Work Hub with central time-entry submission
- Shared time-tracking module with refresh-safe active timer state, Work Hub and Sprint Workspace controls, and central `TIMER` entry submission
- Manager workload cards with member detail and utilization signals
- Manager workload filtering by attention/availability and sorting by load/activity/name
- Company Control Tower summary with delivery and risk signals
- Live project listing with tenant-scoped status cards
- Live sprint listing scoped to the selected project
- Sprint workspace with sprint-scoped work-item query, status filters, context-preserving creation, status progression, and central time logging
- Tenant Administration for member invitations, status control, and feature entitlements
- Project-scoped Releases & Dependency Risk workspace
- In-app Notification Center with unread/read state
- Tenant Administration Telegram channel configuration
- Tenant Administration time-entry policy configuration with an explicit enable/disable switch, rounding, weekend, overtime, and daily-limit controls

The Work Hub, Manager Workload, and Control Tower use typed API clients in normal mode. Demo mode supplies representative data so the responsive UI can be reviewed without an authenticated backend session.

## Feature-based structure

The application shell is intentionally thin. Business screens are grouped by product module so a feature can evolve without spreading its UI across the entire app:

```text
src/
├── app shell (App.tsx)
├── core API/session integration (api.ts)
├── shared/components
└── modules/
    ├── home
    ├── work-hub
    ├── resource-management
    ├── project-management
    ├── sprint-management
    ├── time-tracking
    └── control-tower
```

The module entry points are also the boundary for future route-level code splitting, module entitlements, and feature-specific hooks/API adapters.

## Verify

```powershell
npm install
npm test -- --run
npm run dev              # keep this running in another terminal
npm run test:e2e
npm run build
```

The Playwright configurations intentionally do not own the Vite process. On Windows this keeps browser-test teardown deterministic. The central runner starts and stops Vite automatically; when running Playwright directly, start Vite first. The live-authenticated suite additionally requires the backend and local MySQL/Redis services, so use `testing/run-all-tests.ps1` for the complete workflow.

Run locally:

```powershell
npm run dev
```
## Backend session integration

The shell now supports the backend session contract. In normal mode it checks `GET /api/v1/me` and shows the tenant-bound login screen when no session exists. Vite proxies `/api` to `http://localhost:8080` during development.

The shared API client obtains CSRF protection through `GET /api/v1/auth/csrf`, then reads the browser-readable `XSRF-TOKEN` cookie and sends that cookie value as `X-XSRF-TOKEN` for state-changing requests. All requests include credentials so the tenant-bound HttpOnly session cookie remains attached. Feature modules should use this client instead of implementing their own fetch/CSRF logic.

For visual-only mock mode, set `VITE_DEMO_MODE=true`. For local HTTP backend development, set `SESSION_COOKIE_SECURE=false` on the backend; keep it enabled in deployed HTTPS environments.

Implemented API views:

```text

POST /api/v1/time-entries (Idempotency-Key is generated by the client unless supplied)
GET  /api/v1/manager/workload

GET  /api/v1/projects
GET  /api/v1/projects/{projectId}/sprints
GET  /api/v1/work-items?sprintId={sprintId}
POST /api/v1/work-items
PATCH /api/v1/work-items/{workItemId}

GET  /api/v1/tenant/features
PUT  /api/v1/tenant/features/{featureKey}
GET  /api/v1/projects/{projectId}/releases
```
